# 论文笔记提交流程

适用于用户要求“提交/上传论文笔记”“把最新笔记同步到仓库”。只改笔记或首页时，不自动推送。用户要求提交笔记时，默认包含下列配套更新，无需再逐项询问；执行权限仍按环境审批要求处理。

## 项目作用域

仅当本次请求明确或由当前上下文确定要提交到下述 research-learning-log 仓库时启用。笔记工作区只是这个项目的素材来源，不表示该目录内的所有普通对话都触发。其他项目、普通论文问答、阅读讨论及仅编辑文件不启用此提交流程。不得安装到全局技能目录或修改全局指令。

- 远端：`https://github.com/7alpaca7/research-learning-log`，默认分支 `main`；保留当前可见性。
- 笔记整理工作区：`/home/cancanneed/文档/ChatGPT/论文文献笔记`。
- 原论文常用来源：`/home/cancanneed/workspace/论文`。
- 若用户指定其他来源，以本次指定为准。提到其他对话时，使用对话工具查找并读取最新一轮，核对最终文件；不要将旧对话输出覆盖到较新的文件。

## 提交时一并完成

1. 检查 Git 状态和现有首页，保留用户尚未提交的修改，仅纳入本次相关文件。
2. 确认论文、最新笔记及其引用图片。笔记归入 `notes/YYYY-MM-DD_<论文简称>.md`，不按发表年份分目录；配图归入 `assets/<论文简称>/`。保留原文图与自绘图的来源标注，保留原生数学表达；适配 GitHub 时只调整必要的公式分隔符。
3. 将相应原论文归档为 `originals/YYYY-MM-DD_<论文简称>.pdf`，日期前缀与对应笔记一致，检查标题/版本对应、PDF 文件头及复制前后内容一致。已有同版本不重复存储；不得悄悄替换不同版本。找不到原文时先完成其余工作，明确报告缺失，不伪造链接。
日期前缀优先采用已知实际阅读日期；仅已确认笔记完成日期时采用该日期并注明，均未知时询问用户，不使用论文发表年份代替。再次上传保持原日期前缀，除非用户修正阅读日期。

4. 更新首页总表：论文、阅读状态、阅读时间、方法论关注点、笔记入口。笔记正文添加相对路径原论文链接。首页继续保持简洁，以方法论为主，数学核查是辅助。
5. 完成笔记且用户明确表示读完或精读完成时，及时将状态改为“已精读”；仅整理或上传材料不自动表示读完。已有“已精读”状态不因代码待核查而倒退。时间使用北京时间 `YYYY-MM-DD`，不猜测实际起止时间；只确认笔记完成日期时写“日期（笔记完成）”，不要误填“至今”。状态或关键日期有未决歧义时，使用已知事实并在结果中指出。
6. 首页“更新记录”仅展示实际已上传的论文笔记：最新上传日期、论文链接、简短内容。以论文为单位去重，每篇只留最新一条；再次上传时替换原记录并按最新日期倒序排列，绝不重复追加。内容概括笔记本身，不列公式修复、排版等维护流水。首页、原论文归档和流程配置维护不新增论文记录；没有真实上传不声称已上传。
7. 同步整理工作区首页的对应内容，避免随后从旧副本覆盖正式仓库首页。涉及两个副本时先比较再合并，不整目录覆盖。
8. 检查笔记和首页的相对链接、全部引用配图及 PDF 是否存在，检查 `git diff --check` 和待提交文件列表。不上传对话历史、无关附件或用户未公开的研究创新；有明确隐私要求时遵循最新要求。
9. 仅提交相关文件并推送；不强制推送、不改可见性。遇到远端分歧先检查并保留双方修改；无法安全处理则说明具体阻碍。只有推送成功才能报告“已上传”。没有内容变化则不创建空提交。

## 完成反馈

简要给出笔记的 GitHub 链接，并确认首页状态/时间、原论文归档及更新记录已同步；说明仍缺失的材料或未确认时间。
